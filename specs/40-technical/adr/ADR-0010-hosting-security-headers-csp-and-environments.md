## Context
The tool is a static single-page app served at its own address and embedded by the portal (PRN-05,
RULE-16). The privacy promise must be enforceable, not just asserted: after load, the page makes no
request of its own, nothing outlives the page, and only configured host origins may embed it or
send it settings (NFR-01, NFR-09, INV-04, D-003). The host frame must grant downloads, clipboard
writing and leave-page dialogs and move focus into the tool after the ready signal (RULE-16, D-006;
the portal change request is in `.build-my-app/reports/`). The sibling tools already deploy this
way, so the suite shares one hosting and header approach. Development happens locally only, and
nothing is provisioned before the deploy phase.

## Decision
**Hosting.** Cloudflare static assets via wrangler (DEP-24), assets only, no Worker script, on the
custom domain `image-annotator.tarokit.app` only (`workers_dev: false`, preview URLs off), deployed
by hand by the owner (ADR-0014). Security headers come from a `_headers` file generated by
`scripts/gen-headers.mjs`:
- **Content-Security-Policy**: `default-src 'none'; script-src 'self' '<boot-script-hash>';
  style-src 'self'; img-src 'self' data:; font-src 'self'; worker-src 'self';
  connect-src 'none'; manifest-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none';
  form-action 'none'; frame-ancestors <HOST_ORIGINS>` (empty list → `'none'`, standalone only).
  `connect-src 'none'` is the enforceable core of NFR-01. Decoding a `File`, drawing on a canvas
  and downloading through a `blob:` link need no CSP source, so no relaxation is needed. No
  `'wasm-unsafe-eval'`. `img-src blob:` is added only if SP-decode selects the `<img>` fallback
  (ADR-0005), by a superseding ADR.
- `Permissions-Policy: clipboard-write=(self), clipboard-read=()` plus camera, microphone,
  geolocation and the sibling list off; `Referrer-Policy: no-referrer`;
  `X-Content-Type-Options: nosniff`; `Cross-Origin-Opener-Policy: same-origin`;
  `Strict-Transport-Security: max-age=31536000; includeSubDomains`; `Cache-Control: no-cache` for
  HTML and `immutable` for hashed `/assets/*`. `/sw.js` gets its own CSP
  `default-src 'none'; connect-src 'self'` (it alone fetches the tool's own files, ADR-0011).
- The lint ban on network and storage APIs (ADR-0003) and an e2e server-side request log back the
  CSP; the NFR-01 test calls `fetch` to another origin from the page and expects a CSP refusal. The
  source link uses `rel="noopener noreferrer"` (F-016.R3).

**Host contract (RULE-16).** `HOST_ORIGINS` (build setting, default `https://tarokit.app`,
wildcards refused) feeds both `frame-ancestors` and the runtime allow-list. An inline, CSP-hashed
boot script applies the theme and language from the address before first paint. The `message`
listener accepts only `{ type: 'taro:theme' | 'taro:language', value }` with `event.origin` in the
allow-list **and** `event.source === window.parent`; anything else is ignored. The tool posts one
`{ type: 'taro:ready' }` to the parent with an allow-listed target origin, never `'*'`, never
content — the only message it sends. It never calls `focus()` on itself to take focus from the
host (F-001.R9).

**Environments.**
| Environment | Where | Serves | `HOST_ORIGINS` |
|---|---|---|---|
| local (dev) | `pnpm dev` on localhost | source, hot reload | default, plus the local stub host |
| local (release preview) | `pnpm preview` of the exact `dist/` | the release build; e2e runs against it, including a stub host page on another localhost port for the frame tests (SP-host) | as built for production, plus the stub host for tests only |
| production | Cloudflare static assets, `https://image-annotator.tarokit.app` | `dist/` of the approved release | `https://tarokit.app` |
**No staging in M-1**: the release candidate is verified locally against the exact `dist/` that
ships, and a bad production deploy is rolled back to the previous wrangler version in seconds.
Adding staging later means a second wrangler environment with its own custom domain and
`HOST_ORIGINS`. **Nothing is provisioned** (Cloudflare project, DNS, tokens) before the deploy
phase (phase 7), and only with the owner's approval.

## Alternatives considered
- **A server/app backend** — unnecessary and against PRN-01; a static host with headers is enough.
- **Meta-tag CSP** — cannot set `frame-ancestors`; headers are required (NFR-09).
- **A different static host** — the suite standardises on Cloudflare + wrangler.
- **A staging environment in M-1** — extra domain and deploy for little gain given local release
  preview and instant rollback.

## Consequences
- The privacy guarantee is enforced by header + lint + e2e, not just stated (F-016 is honest).
- Only configured origins can embed the tool or have their messages accepted (NFR-09, RULE-16).
- Until the portal applies the frame grants (D-006), the spec fallbacks apply (F-015.R7).
