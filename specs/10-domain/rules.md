# Rules

Sizes "relative to the image" use the image's shorter side `s` (in pixels) and are rounded to
the nearest whole pixel (halves round up). "Mod" means Ctrl on Windows/Linux and Cmd on macOS.

| ID | Rule |
|---|---|
| **RULE-01** | Input formats: PNG, JPEG, WebP, GIF (first frame only), BMP, and AVIF where the browser can decode it. Anything else (including HEIC, TIFF, SVG, PDF), a file that can't be decoded, or a link or web image that arrives without image data (which is never fetched, NFR-01) is refused with a message; the current session is unchanged. When several files arrive at once, only the first image is used and the user is told. |
| **RULE-02** | Size limits, the same in every browser: a file larger than 50 MB is refused. The image, and the canvas (the frame plus its padding, RULE-14), may each have at most 16,777,216 pixels (4096 × 4096) and at most 16,384 pixels on its longer side. An image over either limit can be opened scaled down to the largest size within both limits, keeping its aspect ratio (each side rounded down), or not opened; the user chooses. An image smaller than 1 × 1 is treated as one that can't be decoded. |
| **RULE-03** | Orientation: the orientation recorded in the image's metadata is applied when the image loads, so the image appears the way the device that took it showed it. No other metadata is read. |
| **RULE-04** | Styles. Palette (in order): red, orange, yellow, green, blue, purple, black, white. Stroke sizes relative to the image: S = max(2, 0.003·s), M = max(3, 0.006·s), L = max(6, 0.012·s). Text sizes relative to the image: S = max(12, 0.025·s), M = max(16, 0.04·s), L = max(24, 0.06·s). A step badge's diameter is 2 × the text size of its size. A highlight's width is 3 × the stroke size of its size. Fill (rectangle, ellipse): none, solid, or translucent (30 % opacity). Default current style per tool: rectangle, ellipse, line, arrow, pen, text and step: red, M, fill none; highlight: yellow, L; redaction: solid, black, strength M. Changing a style while annotations are selected changes those annotations and also becomes the current style for their tools. The current style lasts until the page closes. |
| **RULE-05** | Minimum drag: a drag shorter than 4 screen pixels with a shape, highlight, pen or redaction tool counts as a click. A click with a shape or redaction tool places that annotation at a default size of 20 % of `s` (lines and arrows: pointing right), centred on the click; a click with the pen or highlight tool places a dot. With the select tool, or with Alt held on an annotation while a drawing tool is active (RULE-19), a press on an annotation or handle that moves less than 4 screen pixels is a selection click, not a move or resize, and records no undo step; once the pointer passes 4 pixels, the move or resize follows from the press point. With the select tool, a press on empty canvas that moves less than 4 screen pixels is a click (it clears the selection); beyond that it draws a selection box. |
| **RULE-06** | Constrain: while Shift is held during a pointer drag, rectangles and redactions stay square and ellipses stay circles (side = the longer side of the drag), lines and arrows snap to 45° steps, highlights stay horizontal or vertical (whichever the drag is closer to), and resizing with a corner handle keeps the aspect ratio; with an edge handle the other axis scales by the same factor about the centre; moving a line or arrow end snaps it to 45° steps about the fixed end. |
| **RULE-07** | Steps are numbered 1…n in the order they were created; a duplicated step is a new step and gets the next number (several duplicated together are numbered in their drawing order). Deleting a step renumbers the later ones so the numbers stay consecutive, and undo restores the earlier numbers. A step's badge is a filled circle in its colour (a pill of the same height when the number has 3 or more digits, as wide as its digits plus one text size and never narrower than the circle) with its number at the step's text size. **Contrast pairing**, used here and in RULE-08: black on yellow, orange, green and white; white on red, blue, purple and black; every pairing has a contrast ratio of at least 4.5:1 with the palette's colour values. Step numbers are plain digits in every language. With the step tool, a press that moves places one step at the press point. The badge has no outline (D-029). |
| **RULE-08** | Text: one typeface (the tool's own UI typeface, which covers Vietnamese), sizes per RULE-04, up to 2,000 characters per annotation; extra typed characters are not accepted and a paste is cut to fit. The anchor is the top-left corner of the text box; the box fits the content, growing right and down; lines break only where the user typed a new line. Text has no resize handles; its size is set by S/M/L. Text whose content is empty or only whitespace when editing ends is removed. Text colour is the style colour, with an outline in the contrast pairing colour (RULE-07) of width max(1, 0.08 × text size) pixels. Typed, pasted or dropped text is kept in composed form (Unicode NFC), so a letter entered with separate accent marks looks the same as the same letter entered whole, and the 2,000-character limit counts the composed text. |
| **RULE-09** | Highlight: drawn at 40 % opacity so the image underneath stays readable; overlapping parts of one highlight do not darken each other. Its ends are square; a highlight dot is a square as wide as the highlight. A Shift-constrained highlight is a straight run from the press point (RULE-06). |
| **RULE-10** | Redaction kinds. *Solid*: fully opaque, any palette colour (default black), hard edges, no opacity setting. *Blur*: radius S/M/L = max(6, 0.01·s) / max(10, 0.02·s) / max(16, 0.04·s), default M. *Pixelate*: block size S/M/L = max(6, 0.01·s) / max(10, 0.02·s) / max(16, 0.04·s), default M, blocks aligned to the redaction's top-left corner. Blur and pixelate are computed only from image pixels inside the frame, with every solid redaction already applied, never from other annotations; where their box lies outside the frame they show the background (RULE-14), covering earlier annotations there just as the blurred or pixelated pixels do inside the frame. Where a solid redaction overlaps a blur or pixelate redaction, the solid one shows, whatever their order (INV-02). Blur and pixelate are labelled "not secure" wherever their kind is shown or chosen. |
| **RULE-11** | History: every completed change is one undo step: creating, deleting, moving, resizing or restyling annotations (a multi-selection counts as one step), changing a redaction's kind or strength, reordering, changing the frame or padding (a frame change and the padding reduction it causes, RULE-14, are one step). Creating a text and finishing its first edit is one step; finishing an edit that empties an existing text is one deletion step. Repeated arrow-key nudges or resizes of the same selection, or of the frame, with no other action in between, are one step. Not undo steps: zoom, pan, selection, tool changes, and changes to a tool's current style with nothing selected. At least the last 200 steps are kept. Exporting does not clear the history. Loading a new image or starting over begins a new session with an empty history and can't be undone. |
| **RULE-12** | View: zoom in/out steps through 10, 25, 50, 67, 100, 150, 200, 300, 400, 600, 800 %; from a level between steps it goes to the next step in that direction. The maximum is 800 %. Fit shows the whole canvas, never above 100 %, and may go below 10 % for very long images; zooming out stops at 10 % or the fit level, whichever is lower. A newly loaded image is shown fitted. While the crop tool is active, the content is the whole image instead of the canvas, and Fit shows the whole image; entering or leaving the crop tool keeps the zoom level and, within the pan limits (F-002.R4), the frame's place on screen, except that a fitted view is fitted again. |
| **RULE-13** | Frame: a rectangle of the image in whole image pixels, at least 16 pixels in each dimension (or the image's size in that dimension if smaller), always inside the image; by default the whole image. Padding never moves or resizes it. |
| **RULE-14** | Padding: none, S, M or L = 0, 0.03, 0.06 or 0.12 × the frame's longer side (rounded to the nearest whole pixel), added equally on all four sides of the frame (D-020). The canvas is the frame plus its padding. A size is offered only if the resulting canvas stays within RULE-02's limits; larger sizes are unavailable, and when a frame change would push the canvas over the limits, the padding becomes the largest size that fits (part of the same undo step). Background: transparent (default) or a palette colour, for the whole canvas (visible in the padding and under transparent pixels inside the frame); image pixels outside the frame never show in the padding. Annotations may extend into the padding; parts outside the canvas are kept but never exported. |
| **RULE-15** | Export: PNG, one export pixel per image pixel, covering exactly the canvas (the frame plus its padding, RULE-14); image pixels show only inside the frame; annotations outside the canvas are cut off; transparent areas stay transparent. Download file name: `<source name without extension>-annotated.png` when opened from a file, else `annotated-<YYYYMMDD-HHMMSS>.png` (local time). The source name has control and bidirectional formatting characters and leading dots removed, each of `/ \ : * ? " < > |` replaced with `_`, surrounding spaces trimmed, and is cut to 100 characters, so the saved name is the one the notice shows; if nothing is left, the pasted-image name is used. A copy succeeds when the clipboard accepts the image; a download succeeds when the file has been handed to the browser. |
| **RULE-16** | Host contract. The host passes the initial theme (`light` or `dark`) and the language (RULE-17) in the tool's address when opening it; later changes to either arrive as settings messages. A settings message is accepted only from an allowed origin and only from the page that embeds the tool. The tool signals the host once it is ready; that ready signal is the only message the tool ever sends, and it never carries content. The list of allowed host origins is fixed when the tool is deployed; it decides both who may embed the tool and whose messages are accepted. If the list is empty, the tool cannot be embedded and runs standalone only. The host frame allows downloads, clipboard writing and leave-page dialogs, and the host moves keyboard focus into the tool after the ready signal (D-006); opening new tabs is optional. |
| **RULE-17** | Language: the supported languages are `en-US` (the default) and `vi-VN`. A language value matches a supported language when it equals it ignoring letter case, or else when its primary language (`en`, `vi`) matches; so `vi`, `vi-vn` → `vi-VN` and `en-GB` → `en-US`; anything else is unsupported. The active language is, in order: the latest supported value from an accepted host settings message (RULE-16); else the supported value in the tool's address; else the first of the browser's preferred languages that matches; else `en-US`. An unsupported address value counts as absent; an unsupported message value is ignored. The language decides every user-facing string, the page language, and how numbers and plurals are written; it never changes the export (INV-05) and is never stored. |
| **RULE-18** | Unexported changes: the session has unexported changes when an image is loaded and, since it was loaded or last successfully exported (RULE-15), any undo step (RULE-11) was made, undone or redone. Loading an image by itself is not a change. |
| **RULE-19** | Keyboard map. **Scope:** the Tools, Canvas and Edit keys (including Enter, Tab, arrow keys, Delete/Backspace and Space) act as listed only while the canvas has focus; on any other control (toolbar, panel fields, swatches, status bar) they do that control's normal action. The History, View, Load, Export and Help keys work wherever focus is in the tool, except the single-character keys ?, Shift+1 and Shift+0, which act only while the canvas has focus. No key here acts while text is being edited (a text annotation, or any text or number field), except as stated at the end; while a dialog or menu is open, only Esc acts, closing it; Mod+O is still kept from the browser. Within that scope every key here is kept from the browser, even when it has nothing to act on. **Tools:** V select, R rectangle, O ellipse, A arrow, L line, P pen, H highlight, T text, N step, X redaction, C crop. **Canvas:** Enter with a drawing tool places a new default annotation (RULE-05) at the centre of the view, even if something is selected (text: starts editing it; step: the next number; pen or highlight: a dot); Enter with the select tool and one text selected edits it. Tab / Shift+Tab select the next / previous annotation in drawing order; after the last (or before the first) focus leaves the canvas. **Edit:** Delete or Backspace delete the selection; Mod+D duplicate (offset 10 image pixels right and down); Mod+A select all; ] bring forward, [ send backward; arrow keys move the selection 1 image pixel (Shift: 10); Alt+Right/Left make a single selected box annotation 1 pixel wider/narrower and Alt+Down/Up taller/shorter (Shift: 10), keeping its top-left corner, never below 1 × 1; for a line or arrow they move its head; for a stroke or highlight they scale its bounding box the same way; with several selected or a text or step selected they do nothing. With the crop tool, arrow keys always act on the frame (never pan): arrows move it and Alt+arrows resize it by its right or bottom edge. Otherwise, with nothing selected, arrow keys pan the view by 40 screen pixels (Shift: 200). Esc: cancel the current drag; else close the narrow style sheet (CMP-StylePanel); else end text editing, keeping the text; else clear the selection; else switch to the select tool. **History:** Mod+Z undo; Mod+Shift+Z redo; Ctrl+Y redo on Windows/Linux. **View:** Mod+= (or Mod++) zoom in, Mod+- zoom out, Shift+1 fit, Shift+0 100 %, Space+drag pan, Mod+wheel zoom at the pointer. **Pointer:** Alt+drag moves an annotation while a drawing tool is active. **Load:** Mod+V paste, Mod+O open a file. **Export:** Mod+C copy the result when no text is selected on the page; Mod+S download. **Help:** ? shows the shortcut list. While text is being edited, only Esc and Mod+S keep their meaning; every other key edits the text as in any text field, and undo/redo act within the text. On Latin keyboard layouts letters follow the typed character; on non-Latin layouts they follow the key's position on a US layout. Shift+1 and Shift+0 follow the digit-row key position on every layout; ?, [, ], = and - follow the typed character. The view scrolls to keep a newly placed (Enter, Mod+D) or selected (Tab, or activating its option) annotation visible. |
| **RULE-20** | Redaction count: the number of redactions (any kind) that overlap the canvas (what is exported, RULE-15). It is shown before export next to the export actions and after each successful export (D-007). |
