# Non-functional requirements

Reference machine: a mid-range laptop from the last 4 years (4+ cores, 16 GB RAM) in a current
desktop browser. Reference images: a 2880 × 1800 screenshot (5.2 MP) and a 5120 × 2880
screenshot (14.7 MP).

| ID | Requirement | Measure |
|---|---|---|
| **NFR-01** | Privacy: after first display, the only requests are the browser fetching the tool's own files into the offline cache (and checking for a new version while the page opens); they never carry user content. Every code path (blur and pixelate, decoders, typefaces) is part of that set; nothing is fetched on first use of a feature, and links or web images are never fetched. No analytics. Images and annotations are kept only in memory (INV-04). The tool's content policy forbids connections to any origin other than the tool's own, and the page itself makes none; only the offline cache fetches the tool's own files (D-003). | Network log during a full M-1 session shows only the tool's own files being cached; policy header present, and a request to another origin attempted from the page is refused. |
| **NFR-02** | Responsiveness: while drawing, moving or resizing, the canvas updates every frame at 60 fps on the 14.7 MP image with 100 annotations (including 10 blur/pixelate redactions); other input gets visible feedback within 100 ms; anything longer than 0.5 s shows progress. | Interaction traces on both reference images. |
| **NFR-03** | Speed: the 14.7 MP image opens (paste, drop or file) within 1 s and exports (copy or download) within 1.5 s; the 5.2 MP image within 0.5 s each. | Timed runs on the reference machine. |
| **NFR-04** | Memory: a session with an image at the RULE-02 limit and 200 annotations stays below 1 GB of tool memory; memory from a replaced image is released. | Memory snapshots after load, edit and replace. Tool memory is the OS memory footprint of the tool's page process and its share of the browser's GPU process (minus the GPU process on a blank page); "released" compares the same stage after a warm-up cycle, within 10 %. |
| **NFR-05** | Startup: interactive within 1.5 s on a 10 Mbit/s, 40 ms connection with a cold cache, 0.5 s when cached. The architecture sets a size budget for the initial download. | Lab measurement with throttling. |
| **NFR-06** | Accessibility: WCAG 2.2 AA; every action operable by keyboard; every drag has a single-pointer non-drag alternative (position and size fields, D-008) and a keyboard alternative, except freehand pen and highlight paths (essential); status changes announced (tool change, placing, deleting, duplicating, undo and redo, export results); colour choices named, not shown by colour alone. | Automated audit + manual screen-reader pass. |
| **NFR-07** | Browser support: latest two versions of the Chromium-, Gecko- and WebKit-based desktop browsers; embedded and standalone; single-finger drawing works on the latest WebKit- and Chromium-based tablet browsers (pinch-zoom versus drawing polish is M-2); layout usable down to 320 px wide with no horizontal page scroll. | Automated end-to-end tests on Chromium and WebKit; Gecko manual check per release candidate; manual touch pass on one WebKit-based and one Chromium-based tablet per release candidate. |
| **NFR-08** | Export fidelity: the export matches the on-screen view at 100 % (annotation positions within 1 image pixel, text within 2); solid redactions pass a pixel test and blur/pixelate match the reference effect within ±1 per channel (INV-02); exported files carry no source metadata, hold one image, and show sRGB colours as on screen (INV-03). | Pixel-comparison and file-inspection tests, including a wide-gamut source. |
| **NFR-09** | Embedding safety: the tool can only be embedded by configured host origins and accepts messages only from them. | Header check + message-origin tests. |
