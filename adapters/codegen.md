# Code generation adapter

How build scripts turn specs into code (MOD-Build, ADR-0003, ADR-0010, ADR-0013, ADR-0015). Copied
from the sibling data-analysts-file-viewer and adapted. Generated files are checked in, never edited
by hand, and regenerated by `pnpm gen` (also the first step of `pnpm dev` and `pnpm build`).
`pnpm check` starts with `pnpm gen:check`, which fails when any checked-in output differs from what
the generators produce.

| Generator | Source (spec) | Output (checked in) | Consumed by |
|---|---|---|---|
| `scripts/gen-tokens.mjs` | `specs/30-experience/tokens.json` | `src/app/styles/tokens.gen.css`, `src/app/styles/tokens.gen.ts`, `src/render/palette.gen.ts` | all CSS (`var(--tk-…)`), TS token names, MOD-Render palette |
| `scripts/gen-copy.mjs` | `specs/30-experience/copy.md` | `src/copy/messages.gen.ts` | MOD-Copy `t(id, params)` |
| `scripts/gen-notices.mjs` | `specs/40-technical/dependencies.md` + installed packages | `src/app/third-party-notices.txt` | imported as a URL by the privacy details; shipped as the hashed `/assets/third-party-notices-<hash>.txt`, listed in `tk-assets` (ADR-0025.3) |
| `scripts/gen-headers.mjs` | `src/host/boot.js` + `HOST_ORIGINS` | `public/_headers` | Cloudflare static assets (phase 7), e2e host harness |

`scripts/gen-all.mjs` runs all four; `--check` compares instead of writing.

## Tokens → CSS custom properties and the canvas palette
- Style Dictionary 5 (DEP-13) formats the values; the script only splits the colour themes.
- Names: `--tk-<path in kebab case>`, e.g. `color.lineStrong` → `--tk-color-line-strong`,
  `color.workArea` → `--tk-color-work-area`, `size.toolButton` → `--tk-size-tool-button`,
  `annotation.color.red` → `--tk-annotation-color-red`. Colour names drop the theme segment
  (`color.dark.bg` and `color.light.bg` are both `--tk-color-bg`).
- Scheme (same as the portal): everything inside `@layer tokens`; **dark** values and all
  non-colour tokens on `:root`; **light** colours under `[data-theme="light"]`; a
  `prefers-color-scheme: light` block for `:root:not([data-theme])` (reached only when the boot
  script did not run); `color-scheme` set per theme.
- `contrast` is metadata (the AA pair list, checked by `tools/token_contrast.py`), not emitted.
- `tokens.gen.ts` exports `TOKEN_VARS`, `TokenName`, `Theme`, `THEMES`, `DEFAULT_THEME`, `tokenVar(name)`.
- `palette.gen.ts` exports `PALETTE` (RULE-04 order) and `PALETTE_HEX` from `annotation.color`, so the
  canvas never reads a theme (ADR-0013, INV-05). Generation fails unless `annotation.color` holds
  exactly the eight RULE-04 colours, in order, as `#RRGGBB`.

## copy.md → message catalog
- `copy.md` holds tables `| ID | en-US | vi-VN | Notes |`: one row per string, the ID cell
  `**COPY-<group>.<name>**`, one text column per language right after ID (ADR-0015 §3). The first
  language is the default (RULE-17). Every table must list the same languages.
- A text with a count gives one form per plural category: `one: … · other: …`. A language with a
  single category (vi-VN: `other`) writes its one form without a prefix.
- Generation (and so the build) fails when a string lacks a language, when its `{placeholder}`
  names differ between languages, when its plural forms differ from the language's categories
  (`Intl.PluralRules(lang).resolvedOptions().pluralCategories`), or when a plural string has no
  `{count}` (F-018.AC8).
- Output: `LANGUAGES`, `Language`, `CATALOG[lang][id]` (a string, or the plural forms by category),
  `PLURAL_IDS`, `MessageId` and `MessageParams` (each message's placeholder names, `count: number`
  for plurals), keyed by the ID without `COPY-`. `t()` in `src/copy/index.ts` requires exactly those
  parameters at compile time, fills numbers with `Intl.NumberFormat(lang)` and picks the plural form
  with `Intl.PluralRules(lang)`.
- Rows whose Notes say "deprecated" are skipped.

## Dependency registry → acknowledgements
- Reads every active DEP row (not `removed`/`rejected`, not a recorded-only fallback such as DEP-26
  and DEP-27). The licence cell's SPDX expression is the text before any note (`OFL-1.1 (…)` →
  `OFL-1.1`).
- For **runtime** and **asset** rows, each npm package named in the row that is installed is listed
  with its installed version, licence and licence file text. CC-BY rows (build-time data) get an
  attribution line.

## Boot script and `_headers`
- `src/host/boot.js` is the only inline script. `scripts/lib/boot.mjs` strips its comment-only lines
  and trims it; the Vite plugin in `vite.config.ts` inlines exactly those bytes at `<!--boot-->` in
  `index.html`, and `gen-headers.mjs` puts their SHA-256 in `script-src`. Changing the boot script
  without `pnpm gen` makes `gen:check` fail.
- `HOST_ORIGINS` (space- or comma-separated; default `https://tarokit.app`; empty → `'none'`;
  wildcards, paths and non-https origins other than localhost refused) sets `frame-ancestors` and the
  compiled-in `__HOST_ORIGINS__` allow-list of MOD-Host. The checked-in `public/_headers` uses the
  default.
- Rules: `/*` page policy (the CSP of ADR-0010 incl. `connect-src 'none'`, Permissions-Policy,
  Referrer-Policy, nosniff, COOP, HSTS, `Cache-Control: no-cache`); `/assets/*` detaches
  `Cache-Control` and sets 1-year immutable; `/sw.js` detaches the page CSP and `Cache-Control` and
  sets `default-src 'none'; connect-src 'self'` and `max-age=86400`.
- `public/.assetsignore` keeps source maps and the Vite manifest out of the upload.

## Gates (not generators)
- `scripts/check-size.mjs` (`pnpm check:size`): gzip (level 9, 1 KB = 1,000 bytes) of `index.html`,
  every CSS and startup JS file, the effects worker chunk, and the startup font files as they are,
  against architecture.md "Budgets and baselines" (HTML 12, CSS 18, JS 80, worker 8, fonts 90,
  total 210 KB). Fails on any JS chunk that index.html does not load and that is not the worker, or
  on a `dynamicImports` / dynamic entry in the Vite manifest (no lazy chunks, ADR-0003).
- `scripts/check-licenses.mjs` (`pnpm check:licenses`): `pnpm licenses list --json` against the
  ADR-0001 allow-lists over every installed package, with the named build/dev/test-only exceptions
  (MPL-2.0 `lightningcss*`, `axe-core`, `@axe-core/playwright`; CC-BY-4.0 `caniuse-lite`) and OFL
  for registered font assets; every direct dependency registered and inside its row's version range;
  production dependencies registered as runtime/asset; every transitive production package
  registered. Rows still `proposed` are listed for approval. Then it runs the dist scan.
- `scripts/check-dist.mjs` (`pnpm check:dist`): from the hidden source maps, every third-party
  package whose code reached a shipped chunk must be a registered runtime/asset row under the
  shipped allow-list; shipped fonts must trace to a registered font asset and be a `latin` or
  `vietnamese` subset (D-025); unknown shipped file types fail.
- `scripts/lib/offline.mjs` emits `src/host/sw.ts` as the classic `/sw.js` (ADR-0011) and fails the
  build if it imports page code.
- `scripts/check.mjs` (`pnpm check`, `pnpm check:full`) runs every gate in order; see
  `docs/local-dev.md`.
