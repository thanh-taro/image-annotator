## Findings

### Minor

**m1. Text background label repeats the canvas background label (English)**
- Where: `COPY-style.text_background` = "Background" (`src/copy/messages.gen.ts`, from `specs/30-experience/copy.md`); group "Background" in the text panel. `COPY-canvas.background` is also "Background".
- Criterion: WCAG 2.4.6 Headings and Labels (clear purpose), 3.3.2 Labels. Not a conflict while both are on screen, since the canvas settings show only with nothing selected, but a screen reader user moving between panels hears the same name for two different things. Vietnamese is distinct ("Nền chữ" and "Nền").
- Fix: change the English copy to "Text background" (spec copy change, then `pnpm gen`). The colour group "Background color" can stay, or become "Text background color".

**m2. Focus stays on the swatch after picking a text background colour while editing**
- Where: `ColourGroup` in `src/app/StylePanel.tsx`, text being edited, palette swatch picked. Measured: after Space on Purple, `document.activeElement` is the Purple swatch.
- Criterion: WCAG 2.4.3 Focus Order (usability). Editing correctly continues (F-020.R8, F-005.R3). The user must Tab or Shift+Tab back into the text field to keep typing. `backToText` is wired only for the custom picker (F-019.R9). The Color group behaves the same way, so this is consistent with existing behaviour and not a regression.
- Fix: optional. Either accept it, or have palette picks made while a text is edited call `backToText()`. Doing that would need a spec decision, because it changes the roving-radio arrow-key flow (arrowing would pull focus out of the group). Raise it in the next a11y review of F-019 and F-020 together.

**m3. Caret and text legibility on translucent or equal-colour backgrounds**
- Where: CMP-TextEditor with a text background. `caret-color` equals the text colour (measured rgb(214,40,40) for red text, with the field's own text transparent).
- Criterion: WCAG 1.4.11 Non-text Contrast, 1.4.3 Contrast (user-chosen, so advisory).
  - The automatic background is the RULE-07 pairing colour, so contrast is at least 4.5:1: red on white is 5.0, blue on white is 5.3, orange, yellow and green on black are 8 to 13. Custom colours pair to at least 4.58.
  - A picked colour near the text colour (red text on translucent red, F-020 edge case) leaves text and caret hard to see. F-020 accepts this explicitly ("the text and the caret vanish; the user can pick again").
  - A translucent background (70 %) over a busy image has no guaranteed contrast.
- Fix: none required by the spec. Optional: draw the caret in the box's pairing colour when it is within about 1.5:1 of the background colour. Add a manual check to the release pass (see M5).

**m4. Appearance and disappearance of the colour group is silent**
- Where: Fill → Solid or Translucent (rectangle, ellipse) and Background → Solid or Translucent (text). A new radiogroup ("Fill color", "Background color") appears after the pressed radio. There is no status announcement.
- Criterion: WCAG 4.1.3 Status Messages (advisory). NFR-06 lists only tool change, placing, deleting, duplicating, undo/redo and export as announced.
- Fix: none required. A screen reader user finds the group by moving forward from the radio. Verify in the manual pass (M4). An optional improvement is a polite announcement ("Fill color shown").

### Informational (no action, recorded for traceability)

- I1. The automatic fill colour and automatic background colour show a checked swatch that looks identical to a picked one (F-020.R2 by design). A screen reader cannot tell "automatic Red" from "picked Red". Acceptable per spec.
- I2. Fine-pointer swatches are exactly 24 x 24 CSS px, which meets WCAG 2.5.8 (24 px minimum) with no margin. This is the existing size.
- I3. Esc and Delete pressed on a focused swatch do nothing, and focus stays. This is the same as the Color group.
- I4. Hidden colour input (`input[type=color]`, `tabindex=-1`, `aria-hidden`) is the existing pattern from F-019.
- I5. Forced colours: swatch fills are kept (`forced-color-adjust: none`). The checked swatch keeps its 2 px Highlight border, but the inner surface ring (a `box-shadow`) is dropped. The unchecked custom swatch uses CanvasText. The canvas is a bitmap, so the box and caret are not adjusted. Visible in the emulation screenshot.
- I6. Dark theme reuses the existing tokens, with no new colours.
- I7. Custom swatch names `COPY-style.color_custom` and `COPY-style.color_custom_value` use the same code as the Color group (checked in code, not exercised with a real picker; the e2e suite stubs the picker).

## Automated results (all pass)

**Names, roles, values (AC16)**
- Rectangle and ellipse with fill solid: `radiogroup "Fill color"` with 9 radios (Red, Orange, Yellow, Green, Blue, Purple, Black, White, Custom color), after `group "Fill"`.
- Text: `group "Background"` (None, Solid, Translucent) after Size, then `radiogroup "Background color"` (same 9 radios), then Position and size.
- Each group is named by its label through `aria-labelledby`. The checked radio reports `aria-checked=true`. Automatic colours mark the colour they are drawn in: red text gives White checked, and a text background picked as Red marks Red.
- Fill none or text background none removes the colour group (0 in the tree). The fill and text background choices are native radios.

**Roving tabindex**
- Exactly one swatch has tabindex 0: the checked one, or Red when none is checked. Measured White 0 and the other eight -1.
- Arrow keys move and pick (as the Color group does). Space picks. Picking the checked swatch applies nothing.
- Tab order, wide panel (rectangle): Color group, Size (S/M/L, px field, slider), Fill, Fill color, then the status bar controls. Text: Color, Size, Background, Background color, Position and size, actions. Reading order matches the spec ("after COPY-style.fill", "after the size").

**Focus when a group disappears**
- Fill set to None by keyboard (Space on None): focus stays on the None radio, which remains. Arrow to Solid brings the group back and focus stays on the radio.
- Undo (Mod+Z) with focus on a swatch while the group disappears (Solid undone, or the annotation removed): focus moves to the canvas region (`main.tk-work-area`, "Image canvas") through the existing StylePanel focus-rescue effect. It does not fall to `<body>`.
- Ctrl+Z on macOS does nothing, because Mod is Meta there. This is the existing behaviour.

**axe-core** (wcag2a, wcag2aa, best practice defaults): 0 violations in wide light (rectangle with fill colour, text with background colour, editing), and at 320 px for the rectangle panel in en-US light and dark and vi-VN light and dark.

**Touch layout, 320 px with touch emulation**
- The Fill color and Background color groups are 2 rows of 5, each swatch 44 x 44 CSS px, within 17 to 303 px. This is the same as the Color group.
- The wide panel on a coarse pointer (`pointer: coarse`) gives 2 rows, 44 x 44, for the Color and Fill color groups.
- No horizontal page scroll (document width 320).

**Vietnamese at 320 px**
- Labels "Tô nền", "Màu tô", "Nền chữ", "Màu nền chữ" fit with no clipping (no scrollWidth overflow). "Bán trong suốt" wraps to two lines inside its 44 px choice. The 3 choices measure 95 x 44 each.

**Contrast (WCAG 1.4.11, computed from tokens)**

| Item | Light (surface #fff) | Dark (surface #18121f) |
|---|---|---|
| Unchecked swatch border (line-strong) vs surface | #8c82a2: 3.60 | #6f6290: 3.34 |
| Checked swatch border and focus ring (accent) vs surface | #6837e0: 6.54 | #a47bff: 5.99 |

**Text editor with a background**
- Textarea has `aria-label="Text"` (CMP-TextEditor), a 2 px dashed accent (#6837e0) outline, and padding enlarged by the margin so the outline surrounds the box. It is focused while editing (also after a palette pick, see m2).
- Caret shown in the text colour (red on a white box 5.0:1; on an automatic yellow-text black box 13:1).
- axe reports no violations while editing.
- The accessible name does not mention the background (not required).

**Forced colours (Chromium emulation, `forced-colors: active`)**
- Checked border remains visible, focus outlines use Highlight, the custom swatch uses CanvasText, swatch fills are kept. See I5.
