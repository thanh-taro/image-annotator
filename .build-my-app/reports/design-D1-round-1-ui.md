# Design D1 (components): UI critique, round 1

Source: `canvas/project/*.dc.html` in the session scratchpad. No screenshots, so this critique comes from the CSS.
Checked against `specs/30-experience/tokens.json`, `specs/30-experience/style.md`, RULE-10 and F-007.
The contrast ratios below were computed from the token hex values.
Findings are ordered by impact (usability > clarity > consistency > polish).

| # | Sev | Board / file | Issue → why it matters | Fix |
|---|-----|--------------|------------------------|-----|
| 1 | **blocker** | CMP-StylePanel.dc.html, "tool: redact, blur" (`.kind`) | The Blur and Pixelate options have no "not secure" label. Only the selected one gets the warning box below the list. RULE-10 says blur and pixelate are "labelled not secure wherever their kind is shown or chosen", so a user scanning the choices sees no risk until after choosing. Solid has a shield icon but the unsafe kinds have no visual marker. | Give each of the Blur and Pixelate rows a trailing warning-triangle icon at `size.icon.sm` plus a short "Not secure" tag (`accent2Fg` on `warnBg`, `font.size.xs`/600, `radius.sm`, padding `space.1` `space.2`). Push the tag to the row end with `margin-left:auto`. Copy has no short key yet, so propose `COPY-redact.not_secure_short` in copy.md. Keep the inline `.warn` box under the list as it is (AC5). |
| 2 | **major** | CMP-StylePanel.dc.html `.warn`; Main.dc.html (redaction kind when a blur redaction is selected) | The warning only reads well while the redact tool is active. No board shows the panel with an existing blur or pixelate redaction selected, which RULE-10 also covers ("wherever their kind is shown"). The warning sentence also starts with plain "Not secure:" at 500 weight, so the key words don't stand out from the explanation. | Add a "selection: blur redaction" variant that reuses `.kind` with the tag from #1 and the `.warn` box. Wrap "Not secure:" in `<strong>` (600) so the label scans first. Keep the icon top-aligned as it is now. |
| 3 | **major** | CMP-Toolbar.dc.html / Main.dc.html `.ib.on`; StylePanel `.seg button.on` | The active tool's fill (`selection`) and border (`selectionLine`) are both under 3:1 against `surface`. Ratios: `selectionLine`/`surface` is 1.84 (dark) and 1.74 (light); `selection`/`surface` is 1.19 and 1.17. In practice the only cue left is the icon turning `accent`, which is colour alone and breaks style.md principle 2 and WCAG 1.4.11. The segmented control's `.on` state has no border at all. | Draw the active border in `accent` instead of `selectionLine`, at `border.width.hairline`. Ratios: `accent`/`selection` is 5.0 (dark) and 5.6 (light); `accent`/`surface` is already in `contrast.pairs`. For `.seg button.on`, add `box-shadow: inset 0 0 0 1px var(--accent)`. Then match `.kind button.on`, which already uses `accent`, so all three selected states look the same. Optionally add `selectionLine`/`surface` ≥3 to `contrast.pairs` and darken the token instead. |
| 4 | **major** | CMP-StatusBar.dc.html `.ok` (privacy badge button, wide and narrow); `.lnk` | The privacy badge opens a dialog (`aria-haspopup`) but has `padding:0`, so its hit area is about 16 px tall. That is below `size.targetMin` (24). The narrow variant is a bare 16 px icon. The source link is the same. | Give `.ok` and `.lnk` `min-height: size.targetMin` (24px) and padding `0 space.1`. Give the icon-only narrow variants `min-width: 24px`. Add `radius.sm` and a `surface2` hover so both read as buttons, the same as `.zb`. |
| 5 | **major** | CMP-Canvas `.chip` (11px); CMP-ShortcutHelp `.grp h3` and `kbd` (11px) | Text is below `font.size.xs` (12), which principle 4 forbids. The canvas chip is the one label that floats over busy screenshots, where small text is hardest to read. | Set the chip and shortcut `kbd` to `font.size.xs` (12px), with the chip in mono 500. Set the group headings to `font.size.xs`/600 `muted` with no uppercase. That matches the panel `.h` headings and keeps one heading style. |
| 6 | **major** | CMP-StylePanel "canvas (4096 px image)" `.seg button:disabled` | The disabled padding options use `text-decoration:line-through` and give no reason. Struck-through text is hard to read and looks like "deleted" rather than "unavailable", and the user can't tell why they can't add padding. | Remove the line-through and keep `muted`. Add a `muted` `font.size.xs` line under the control, such as "Padding is off: the image is already at the 4,096 px limit". That needs a new COPY key, so propose it in copy.md. |
| 7 | **major** | All boards: spacing values off the token scale | Spacing breaks the 4/8/12/16 rhythm: toolbar `.sep` margin 6, `.tbtn` gap 6 and padding 10, panel `.acts` gap 6, `.fl` gap 6, status bar padding 10, notice gap 10, dialog padding 18/18/14 with h2 margin 6 and p margin 14, ShortcutHelp padding 16/18 with `.hd` and `.grp` margin 10, popover padding 14 and gap 10, empty-state `.btn` padding 14. Neighbouring components end up a few pixels out of line, which shows in a chrome this dense. | Snap to tokens. 6 becomes `space.2` (8), except `.sep` margin and `.tbtn` icon gap, which become `space.1` (4). 10 becomes `space.3` (12) for horizontal padding and `space.2` for gaps. 14 and 18 become `space.4` (16). Dialog: padding `space.4`, h2→p `space.2`, p→actions `space.4`. Status bar padding: `0 space.2`, so it lines up with the toolbar's 8px start padding. |
| 8 | minor | Toolbar/Main `.tbtn` (28) vs `.ib` (32); EmptyState `.btn` and Dialog `.btn` (32); menu items (32); status `.tbtn` (24); panel and notice `.btn` (28) | There are four button heights. In the toolbar, the hover fill of Open/Download (28) sits 4px shorter than the tool buttons next to it (32), so the row looks ragged on hover. | Inside the 40px toolbar, make every button `size.toolButton` (32). Use `size.control` (28) for panel, notice and inline buttons. Dialog, empty-state and menu-item buttons can stay at 32, but document 32 as the "standalone/menu" height in style.md. Status bar controls stay at `targetMin` (24). |
| 9 | minor | CMP-StylePanel/Main `.sws` (8 swatches, 4px gap, `1fr` columns); background row (9 columns) | The swatches are 24px fixed inside about 27.5px columns, so they hug the left with about 3.5px of empty space at the right edge. The selected ring (2px outline at 2px offset) needs 4px, which uses the whole 4px gap and touches the next swatch. | Colour row: use `grid-template-columns:repeat(8,24px); justify-content:space-between`. That gives 8×24 + 7×8 = 248, exactly the panel's inner width, so the effective gap is `space.2`. Background row (9): set the ring to `outline-offset:1px`, or wrap it to two rows with `space.2` gaps. |
| 10 | minor | CMP-StylePanel crop `.fl input` (64px) vs Main.dc.html (56px) | The number field is a different width in two places, and the token `size.field` is 56px. | Use `size.field` (56px) everywhere. Four-digit mono values at 13px fit, at about 45px including padding. |
| 11 | minor | CMP-ConfirmDialog `.dlg` radius 12, h2 16px; ShortcutHelp `.dlg` radius 12, h2 16px; `kbd` radius 5/4; drop border 1.5px; handles border 1.5px | These radii, sizes and widths are off-token. | Use `radius.md` (10) for dialogs, `radius.sm` (7) for `kbd`, h2 at `font.size.lg` (17)/700, and the empty-state dashed border and crop/handle borders at `border.width.focus` (2px) or `hairline` (1px), not 1.5. |
| 12 | minor | CMP-Notice `.ic` 18px, close icon 14px; StatusBar badge icon 14px; redaction pill icon 12px | Icon sizes fall outside `size.icon.sm`/`md`, which makes icons look slightly mismatched across components. | Use `size.icon.sm` (16) for the notice, close, status bar and pill icons. If 16 is too heavy for the 22px pill, drop the pill icon. |
| 13 | minor | CMP-Canvas "selected" outline 1px vs crop frame 1.5px | The two outlines use different weights. On a busy screenshot, a 1px `selectionOutline` is easy to lose. | Use `border.width.focus` (2px) for both the selection outline and the crop frame. |
| 14 | minor | CMP-Notice "progress"; spinner `animation:spin` | There is no reduced-motion variant (style.md Motion). | 15 | minor | CMP-ConfirmDialog `.btn.pri` on Replace and Start over; CMP-DropOverlay uses `cropDim`; Main sample image `border-radius:2px` | The destructive confirms use the accent fill, which breaks "Copy is the only filled control" without a documented exception. The drop overlay reuses a crop token for something unrelated. The canvas should be square-edged (principle 7). | Either record "a dialog's confirm action may be filled" in style.md, or make the confirm an outlined button with `danger` text. Use `scrim` for the drop overlay. Set the canvas radius to 0. |

## Keep (apply elsewhere)
- Dialogs open with focus on **Cancel**, and the "unfocused (embedded)" empty state names the extra click needed before pasting. Both make the iframe's paste behaviour clear to users.
- On narrow widths, Download moves into the overflow menu and zoom collapses to "31 % ▾". This pattern fits other dense rows.
- The error notice uses `dangerBg` + `danger` with an inline recovery action (Download). Every error notice should offer an action like this.
- Annotation colours stay out of the chrome, and annotation text draws in Manrope 600 with an outline (the Vietnamese sample renders).
