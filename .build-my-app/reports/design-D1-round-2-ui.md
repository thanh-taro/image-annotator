# Design D1 (components): UI critique, round 2

Source: the session scratchpad's `canvas/project/CMP-*.dc.html` files. Main.dc.html is excluded because it is redone in D3.
There are no screenshots, so this critique comes from the HTML/CSS. It is checked against `specs/30-experience/tokens.json` and `style.md`.
Findings are ordered by impact (usability > clarity > consistency > polish).

**Totals:** 15 round-1 findings: 9 fixed, 5 partly fixed, 1 regression (#15, the dialog hierarchy). There are 15 new findings: 0 blockers, 6 major, 9 minor.

## 2. New issues and regressions

| # | Sev | Board / file | Issue → why it matters | Fix |
|---|---|---|---|---|
| N1 | **major** | CMP-StylePanel `.seg` (`overflow:hidden`); CMP-Toolbar narrow `.tools` (`overflow-x:auto`) | The focus ring is clipped. The outline sits 2–4px outside the button. `.seg` clips it at its padding edge, so on "Medium" only two vertical slivers show over the neighbouring buttons. Because `.on` is also an `accent` inset, a focused-and-selected item looks almost the same as one that is only selected. The narrow tool scroller has the same problem: `overflow-x:auto` forces `overflow-y` to clip, and the 48px row has only 2px around each 44px button. The board hides this with an inline `overflow:visible`. A keyboard user loses track of focus in the two most-used controls. | `.seg`: remove `overflow:hidden` and round the ends instead, with `:first-child{border-radius:6px 0 0 6px}` and `:last-child{border-radius:0 6px 6px 0}`. `.tools`: use `outline-offset:0` inside the scroller (needs 2px, which the row has), or give the scroller `padding-block:space.1`. Remove the inline `overflow:visible` so the board shows the real behaviour. |
| N2 | **major** | CMP-Toolbar / narrow 390 (tools row) | 8 × 44 + 7 × 4 = 380, so only Select … Text fit. Step, **Redact** and Crop are off-screen with nothing to show the row scrolls. Redact is the privacy-critical tool, and on a phone it is undiscoverable. | Add a `space.6` (24px) fade mask on the scrolling edge: `mask-image: linear-gradient(to right, #000 calc(100% - 24px), transparent)`. ## Keep (apply elsewhere)
- A 2px `accent` inset on every selected state (tool, segment, redaction kind). It is consistent and does not rely on colour alone.
- The colour swatch row maths (8 × 24 + `space-between` = 248) and the inset selected ring, which stays distinct from the focus ring.
- Narrow variants switch to 44px targets and move secondary actions into menus. Extend this to the status bar (N4).
- The "selection: blur redaction" panel repeats the tag, the warning and Use solid. This is a good pattern for any state that shows a risk.
